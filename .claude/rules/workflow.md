# Workflow Rules

## Objetivo

Mantener un flujo de desarrollo controlado y reproducible.

## Reglas obligatorias

- Nunca trabajar directamente sobre main.
- Crear una rama por tarea usando feat/, fix/ o chore/.
- Usar Conventional Commits.
- Crear Pull Request antes de integrar cambios.
- Incluir pruebas junto con los cambios de código.
- Ejecutar validaciones antes de finalizar una tarea.
- Mantener cada cambio con un alcance acotado.
- Documentar decisiones relevantes antes de modificar arquitectura.
